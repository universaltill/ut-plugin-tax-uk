What this does

UK VAT law (HMRC VAT Notice 709/1) treats most cold food differently depending on how a customer takes it: zero-rated when taken away, but standard-rated when eaten on the premises. This plugin applies that switch automatically at checkout — you don't need to ring up a different item or remember to change anything by hand.

How it decides

  • Takeaway order — no change. The item's own tax code (usually zero-rated) applies as normal.
  • Eat-in order — if the item's tax code is one you've configured below, its rate is switched to the standard rate for that sale. If the tax code isn't configured, nothing changes — this covers items you never want switched, like hot food and drinks, which are standard-rated regardless of eat-in or takeaway and don't need this plugin's help.

Configuring which tax codes switch

Open this plugin's settings and edit eatin_standard_rate_by_tax_code — a JSON object mapping one of your shop's own tax code IDs to the standard rate you want applied for eat-in, in basis points (2000 = 20%): 

{"tax_zero": 2000}

This maps your zero-rated tax code to 20% VAT when a sale is marked eat-in. To find a tax code's ID, open Catalog, open any item using that code, and check its Tax code field — the same codes also appear in that field's suggestion list. You can list more than one tax code if your catalog uses several zero-rated codes for different categories of cold food.

What this plugin does not do

  • It doesn't touch hot food/drink — those keep whatever tax code you assigned them directly in the catalog.
  • It doesn't make the eat-in/takeaway choice for you — that's the order type toggle already on the sale screen and self-order kiosk.
  • It's a simplified reading of Notice 709/1 covering the common cold-food case; unusual combinations (mixed hot/cold platters, catering, delivery) aren't modelled and may need a manual override.
